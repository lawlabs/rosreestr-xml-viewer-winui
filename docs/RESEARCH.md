# Исследование и переосмысление

Исследование источников: 14 октября 2026 года; повторная загрузка официального пакета и проверка приложения: 15 октября 2026 года. Цель — современный локальный инструмент работы с уже полученными выписками, полезный для юридической и кадастровой практики.

## Старое приложение

Изучены `APPMain.pas/.dfm`, `APPXMLViewer`, `APPOfflineXMLThread`, `APPRegistryFromXML`, `APPOwnersRegistry`, `APPFlatsInBuildings`, `APPComparator`, конфигурация, `Common/ROSREESTRHelper.pas`, наборы XSL и реальные XML из `Resources/XLT/Extract`.

Смысл приложения шире одного XML-просмотрщика: пакетное открытие и печать, PDF, реестры объектов и правообладателей, извлечение кадастровых номеров, сравнение списков, поиск помещений в зданиях, переименование файлов и локальная работа с сохранёнными преобразованиями. Пользовательская папка содержит также уже созданные PDF, XLSX, базы и архивы результатов обработки.

Технологический долг: VCL и браузерный механизм Internet Explorer/MSXML, извлечение части сведений регулярными выражениями, загрузка связанных XSL и словарей в рекурсивной очереди, проверка интернета через сторонний сайт, HTTP-запрос к `rosreestr.ru/api/online/fir_object/`, жёсткое подключение новых шаблонов с `legalcalc.ru`. В некоторых поставлявшихся новых шаблонах цикл `plans/plan` вообще не выводит изображение. Структура старых кадастровых XML отделяет объект `Realty/Building` или `Realty/Flat` от прав в дополнительном `eDocument`; механическое чтение только `ExtractObject` теряет характеристики.

Перенесены основные полезные сценарии. Рекламные переходы, регистрационные ограничения, сторонние юридические калькуляторы и изменение получателя в подписанном XML не входят в новую модель. Экспорт сохраняет исходник; редактирование подписанного документа не предлагается как обычная операция.

## Актуальные источники

1. **XML, SIG, готовый PDF.** Разъяснение Роскадастра, опубликованное муниципальным органом 25.09.2025, описывает XML с отдельной подписью и дополнительное формирование PDF в ФГИС ЕГРН, а также официальные способы проверки подписи. Отсюда решение открывать весь пакет и сохранять различие между исходным PDF и отчётом приложения. [Источник](https://www.gobogdanovich.ru/index.php/novosti/informatsiya/5642-svedeniya-iz-egrn-v-elektronnom-vide).

2. **Карта.** Информационный выпуск Роскадастра описывает публичную кадастровую карту на НСПД и получение справочных сведений через эту платформу. Кнопка карты направляет на `nspd.gov.ru/map?thematic=PKK`. Данные карты не подменяют содержимое конкретной выписки. [Источник Роскадастра](https://roscadastre.ru/html/news_2025/now_2025.pdf).

3. **Отсутствующая графика.** Порядок предоставления сведений допускает запрос выписки об основных характеристиках без графической части через единый портал; порядок заполнения предусматривает соответствующую отметку. Это один из возможных источников отсутствия плана, а не универсальное объяснение каждого пустого XML. [Порядок предоставления](https://base.garant.ru/400749107/53f89421bbdaf741eb2d1ecc4ddb4c33/), [порядок заполнения](https://base.garant.ru/74637124/f52b32b623103013c77c8c319c288f45/).

4. **Ограниченные сведения о владельцах.** Материалы Роскадастра и действующий порядок различают общедоступные сведения и основания для получения персональных данных. Пустое ФИО не должно считаться ошибкой программы и не восполняется предположениями. [Материалы Роскадастра](https://roscadastre.ru/html/news_2022/2022.pdf), [порядок](https://base.garant.ru/400749107/53f89421bbdaf741eb2d1ecc4ddb4c33/).

5. **Семейства XML.** Имена современных документов сверены с фактическими XML пользователя и документацией разработчика NextGIS для собственного импортёра Росреестра. Реальный файл и его namespace/version остаются источником определения формата; это не проверка наличия самой последней официальной редакции каждой XSD. [Документация NextGIS](https://docs.nextgis.ru/docs_rosreestr_tools/source/rr-import.html).

6. **WinUI.** Основа — официальный шаблон Microsoft, .NET 10, Windows App SDK 2.5.1, WinApp CLI 0.7.1. API проверялись по восстановленным зависимостям проекта. Выбраны штатные CommandBar, NavigationView, ListView, InfoBar и системные диалоги файлов Windows App SDK. WebView2 показывает только локально подготовленные страницы и PDF. [WinUI](https://learn.microsoft.com/windows/apps/winui/winui3/), [WebView2](https://learn.microsoft.com/windows/apps/develop/ui/controls/webview2).

Через исследовательский веб-инструмент каталог не загрузился, однако прямой HTTPS-запрос с текущего компьютера успешно открыл официальный сайт. Проверены разделы выходных документов для земельных участков и ОКС. На них доступны в том числе пакеты `KPT_v10`, `KPZU_v06`, `KVZU_v07`, `KPOKS_v04`, `KVOKS_v03`. Эти старые кадастровые семейства нельзя автоматически считать XSD для XML с корнем `extract_about_property_*`. [Земельные участки](https://rosreestr.gov.ru/activity/okazanie-gosudarstvennykh-uslug/vedenie-egrn/xml-skhemy/5-vykhodnye-dokumenty-zemelnyy-uchastok/), [ОКС](https://rosreestr.gov.ru/activity/okazanie-gosudarstvennykh-uslug/vedenie-egrn/xml-skhemy/6-vykhodnye-dokumenty-oks/).

Официальный `KVZU_v07.zip` скачан для проверки структуры зависимостей (191535 байт, SHA-256 `C1BEFA3BD25FCC6AA951BE8F244B7594E3818CFE2E745FD52131402C457537FD`). Ссылки из основной XSD идут в соседнюю `SchemaCommon`; проверка должна разрешать их внутри выбранного пакета, не разрешая произвольный доступ за его пределы. Действующая официальная XSD для каждого современного семейства и скачивание планов через авторизованный личный кабинет пока **не подтверждены**. Старый `cc_vizual` не открылся из-за ошибки SSL; успешный GET каталога не подтверждает работу этого сервиса. [Пакет KVZU](https://rosreestr.gov.ru/upload/Doc/10-upr/KVZU_v07.zip).

## Что показал пользовательский набор

В локальном непубличном наборе для проверки найдены 4998 XML, 16266 ZIP и 17525 PDF; также есть несколько XLSX, RTF, DOCX и баз старых приложений. Значительная часть файлов дублируется между папками и архивами. Для проверки использовались оригиналы на месте. Персональные данные, сами XML и исходные PDF в репозиторий не копировались.

Набор включает `Extract`, `KPOKS`, `KVOKS`, `KVZU`, современные выписки о зданиях, помещениях, машино-местах, переходе прав и `exract_notice_absence_request_info_12` (историческое написание корня сохранено). Уведомления вынесены в отдельное представление. Выписка о здании может содержать основной объект и десятки связанных `room_record`; для них создаются отдельные строки.

Обнаружены внутренние `file_link` с адресом архивного сервера и `file_storage_path/path`, заканчивающиеся `EXT_FILE`. Это не готовые URL общедоступного портала. Не используется попытка попасть на внутренний IP или сконструировать неизвестную ссылку на сервер. Для таких планов нужен фактический файл из результата услуги либо официальный PDF. Старый собственный XSL также не гарантирует их восстановление.

Статистика последнего полного прохода записывается в `artifacts/corpus-audit.json`: количество исходных файлов, различных XML-объектов/PDF, распознаваемых корней, записей с характеристиками и категориями ошибок. Она показывает читаемость набора и извлечение известных разделов, но не юридическую достоверность и не соответствие всех полей XSD.

## Порядок работы с графикой

1. Использовать готовый PDF или изображение, присутствующее в полученном пакете.
2. Если XML содержит настоящий публичный HTTPS-адрес — загрузить файл по отдельной команде, ограничивая домены, перенаправления, время и размер. Проверять сигнатуру содержимого, чтобы страница ошибки не стала изображением. Сохранять результат в локальном кэше.
3. Если есть координаты — построить самостоятельную схему и каталог точек. Для МСК X обычно соответствует северу, Y — востоку; это не координаты longitude/latitude. Системы координат не смешивать.
4. Если координат и графического файла нет — показать отсутствие исходных данных и официальный путь получения документа. План квартиры нельзя вывести из одной площади, этажа или адреса; контур здания не определяет внутреннюю планировку.

В этой версии площадь считается только для явно замкнутого кольца, без определения отверстий и объединения. Значения имеют исходные единицы. Для геопривязки понадобятся подтверждённые параметры конкретной МСК, зоны и преобразования; до этого GeoJSON с выдуманным WGS84 не экспортируется.

## Восстановление печатной формы

IE применял `xml-stylesheet` и XSLT, формируя HTML по шаблону. Для новой версии преобразование перенесено в .NET `XslCompiledTransform`; WebView2 получает готовую страницу. Это сохраняет таблицы и CSS и не зависит от поддержки XSLT внутри браузера. [Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.xml.xsl.xslcompiledtransform?view=net-10.0), [изменения Chromium](https://developer.chrome.com/docs/web-platform/deprecating-xslt).

Из непустых файлов старого кэша сформирован локальный каталог: четыре архивных пакета с `portal.rosreestr.ru` и четыре сторонних с `legalcalc.ru`. Стороннее происхождение отмечается в интерфейсе. Каталог содержит версии/namespace, URL и SHA-256. Полная таблица, исключения и адаптации — `Templates/SOURCES.md`. XSD и XSL имеют разное назначение: проверка структуры XML не восстанавливает его печатное оформление.

Найдено практическое отличие IE8 от HTML5: `rowspan=0` в шаблоне перехода прав приводил к сдвигу ячеек в Chromium. Результат преобразования адаптирован к семантике старого движка; исходные XML/XSL не меняются. Готовый PDF из пакета имеет отдельный режим и сохраняется побайтно. Его связь с XML устанавливается по имени файла, а не по соседству или кадастровому номеру; несопоставленные PDF из ZIP показываются самостоятельными документами.
